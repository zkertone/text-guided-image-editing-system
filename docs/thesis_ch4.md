# 第4章 系统设计

## 4.1 系统总体组成

本系统围绕《基于大模型的文字驱动图像编辑方法与系统实现》这一课题开展工程实现，整体采用“预训练模型调用与功能模块集成”相结合的方式完成。系统不涉及从零训练扩散模型，也不对底层生成模型结构进行改造，而是在 Hugging Face Diffusers 提供的预训练管线基础上，结合图像预处理、交互界面构建、结果保存和实验记录等环节，形成一个可运行的文字驱动图像编辑原型系统。

从总体组成上看，系统主要包括模型加载部分、图像编辑处理部分、界面交互部分以及实验记录与案例整理支撑部分。模型加载部分负责加载不同编辑任务所需的预训练推理管线，并完成运行设备选择与推理环境初始化；图像编辑处理部分负责组织不同模式下的推理流程，包括输入图像处理、Mask 处理、控制图生成以及推理结果返回；界面交互部分基于 Gradio 实现，为用户提供图像上传、编辑指令输入、参数调节、局部区域指定和结果展示等功能。除核心编辑流程外，系统还包含输入输出图像自动保存、实验信息摘要展示、CSV 实验日志记录、版本记录整理和案例资产整理等配套内容，以支持后续实验分析、论文写作和答辩展示。

结合当前实现情况，系统代码主要集中在 `app` 目录下，文档与实验材料分别存放于 `docs`、`assets` 和 `data` 等目录中。这种组织方式有助于将业务代码、运行数据与论文支撑材料分开管理，便于后续维护、测试与整理。

## 4.2 核心模块设计

系统核心模块主要包括主入口模块、模型加载模块、图像编辑模块和界面交互模块。主入口模块位于 `app/main.py`，主要负责完成系统启动过程中的初始化工作。该模块首先读取 Gradio 启动所需的环境变量配置，然后调用模型加载模块完成预训练推理管线初始化，接着创建图像编辑器对象并构建 Gradio 界面，最后启动整个系统。该部分不直接参与具体图像编辑计算，而是承担系统调度与启动管理功能。

模型加载模块位于 `app/pipeline_loader.py`，用于统一管理系统所依赖的预训练模型管线。根据当前实现情况，该模块已集成三类推理管线，分别对应整体编辑、局部编辑和结构保持编辑三种功能模式。其中，整体编辑模式使用 InstructPix2Pix 管线，局部编辑模式使用 Stable Diffusion Inpainting 管线，结构保持编辑模式使用基于 Canny ControlNet 的 Stable Diffusion ControlNet 管线。该模块在加载模型时还会自动检测当前运行设备，并根据 CPU 或 GPU 环境设置合适的数据类型，同时在 GPU 环境下启用一定的显存优化策略，以提高推理的稳定性和可用性。

图像编辑模块位于 `app/editor.py`，是系统的核心业务模块。该模块负责接收来自界面的输入数据，并根据当前模式调用不同的推理逻辑完成图像编辑任务。在整体编辑模式下，模块对输入图像进行统一预处理后，将图像和文本指令送入 InstructPix2Pix 管线生成结果；在局部编辑模式下，模块除处理原图外，还需接收用户上传的黑白 Mask 图，或将在线绘制区域转换为标准黑白 Mask，再送入 Inpainting 管线完成局部区域编辑；在结构保持编辑模式下，模块会先根据输入图像自动提取 Canny 边缘图，再将该控制图作为 ControlNet 的条件输入参与推理。除推理流程外，该模块还承担输入图、输出图和控制图的保存、实验摘要生成以及实验日志追加记录等任务，是连接模型推理与界面展示的关键部分。

界面交互模块位于 `app/ui.py`，主要负责构建用户可直接操作的前端界面。该模块基于 Gradio 实现，当前界面已经支持编辑模式切换、原图上传、Mask 图上传、在线绘制 Mask、文本指令输入、推理参数调节、结果图展示、Canny 控制图展示以及实验信息展示等功能。为了提高界面可用性，模块还根据不同编辑模式动态控制相关控件的显示与隐藏，从而减少无关参数对用户操作的干扰。整体来看，该模块承担的是系统交互流程组织和结果可视化展示的任务。

## 4.3 系统运行流程

系统运行时，首先由主入口模块完成初始化过程。程序启动后，会读取当前环境中的启动参数，并调用模型加载模块加载预训练推理管线。模型加载完成后，系统根据管线对象创建图像编辑器实例，并进一步构建 Gradio 交互界面，最终进入可交互运行状态。此时，用户即可在浏览器中访问系统界面并进行图像编辑操作。

在具体使用过程中，用户首先需要选择编辑模式。若选择整体编辑模式，则仅需上传原始图像并输入英文编辑指令，同时可设置推理步数、图像引导强度和文本引导强度等参数。系统接收到输入后，会先对图像进行统一尺寸和颜色空间处理，再调用 InstructPix2Pix 管线完成整体图像编辑，并返回编辑结果。若选择局部编辑模式，用户除上传原始图像外，还需指定待编辑区域。当前系统支持两种局部区域指定方式，一种是直接上传黑白 Mask 图，另一种是在线绘制 Mask。无论采用哪种方式，系统最终都会将待编辑区域转换为标准黑白 Mask，并与原图和文本指令一起送入 Inpainting 管线完成局部区域编辑。若选择结构保持编辑模式，用户只需上传原图并输入英文提示词，系统会自动从输入图像中提取 Canny 边缘图，并将该控制图作为结构约束条件输入到 ControlNet 管线中，以得到在保持原始轮廓基础上的生成结果。

在推理完成后，系统会自动保存输入图像、输出图像以及必要的控制图像，并在界面中展示实验信息摘要。摘要内容包括当前编辑模式、模型名称、运行设备、提示词、推理参数以及文件保存路径等信息。同时，系统还会将本次实验的关键参数和结果路径追加写入 CSV 实验日志中，以支持后续实验对比、案例整理和论文写作。由此可见，系统已经形成了从模型加载、界面交互、推理执行到结果保存与实验记录的完整运行流程。

## 4.4 已实现功能概述

结合当前项目实现情况，系统已经具备三类主要图像编辑功能。第一类是基于 InstructPix2Pix 的整体编辑功能。该功能面向整幅图像进行语义驱动修改，适用于整体色调调整、背景变化和风格变化等任务。用户只需输入原始图像和文字描述，系统即可根据文本语义生成相应的编辑结果。第二类是基于 Inpainting 的局部编辑功能。该功能允许用户指定局部区域进行有针对性的图像修改，相比整体编辑更适合目标明确的局部替换或属性调整。当前系统已支持上传黑白 Mask 图和在线绘制 Mask 两种局部区域指定方式，能够满足基础的交互式区域编辑需求。第三类是基于 Canny ControlNet 的结构保持编辑功能。该功能通过自动提取原图边缘结构并将其作为控制条件输入，使生成结果在一定程度上保持原始图像的主要轮廓与结构关系，适用于在保留场景结构基础上进行风格化变化。

除核心编辑功能外，系统还实现了较为完整的配套功能。系统已经具备 Gradio 可视化交互界面，能够支持图像上传、Mask 指定、参数调整和结果展示等基本使用流程；支持输入图像、输出图像和控制图像的自动保存，便于实验留档与结果追踪；能够在界面中显示实验信息摘要，包括模型名称、运行设备、提示词、推理参数、控制方式以及文件保存路径等内容；同时还实现了 CSV 格式的实验日志记录功能，可自动保存每次实验的关键信息，为后续实验整理和案例分析提供数据支持。在项目文档方面，当前系统已经建立了版本迭代记录、实验记录模板、案例索引和案例资产目录，能够较好地支撑后续论文写作、图表整理和案例展示工作。

总体来看，当前系统已基于预训练模型实现整体编辑、局部编辑和结构保持编辑三种模式，并配套完成了界面交互、结果保存、实验记录和案例整理等功能。作为一个面向本科毕业设计的图像编辑原型系统，其已能够为后续实验分析、案例展示和论文撰写提供支撑。

## 4.5 系统总体架构设计

从整体实现方式来看，本系统采用“预训练模型管线 + 编辑逻辑封装 + 可视化交互界面 + 实验记录支撑”的架构思路进行设计。系统并不重新训练底层模型，而是在已有预训练模型的基础上，通过统一的工程组织方式完成不同编辑模式的集成，从而实现文字驱动图像编辑系统原型的构建。

在系统总体架构中，底层为预训练模型管线部分，主要包括 InstructPix2Pix 整体编辑管线、Stable Diffusion Inpainting 局部编辑管线以及基于 Canny ControlNet 的结构保持编辑管线。该部分负责根据输入图像、文本指令以及必要的条件信息完成图像生成或编辑推理，是系统功能实现的基础。在预训练模型管线之上，为编辑逻辑处理部分。该部分主要负责对用户输入进行统一组织，并根据当前所选模式调用相应模型管线完成推理，其处理内容包括输入图像预处理、Mask 数据处理、在线绘制区域转换、Canny 边缘图提取、参数传递、结果返回以及实验摘要生成等。该部分起到承上启下的作用，一方面连接底层预训练模型，另一方面为上层界面交互提供统一调用接口。

再上一层为用户交互部分，即基于 Gradio 构建的可视化界面。该部分面向用户提供图像上传、编辑模式切换、文本提示词输入、参数调节、Mask 上传或在线绘制、结果图展示以及实验信息展示等功能。通过该部分，用户无需直接接触模型代码即可完成图像编辑操作，从而提高了系统的可用性和演示性。除上述三部分外，系统还设置了结果保存与实验记录支撑部分。该部分主要负责输入图像、输出图像和控制图的自动保存，并将提示词、推理参数、运行设备、结果路径等信息记录到实验日志文件中。同时，系统通过版本记录、案例索引和案例目录对项目材料进行整理，为后续论文写作、实验分析和答辩展示提供支持。

因此，本系统的总体架构并非单纯围绕模型调用展开，而是强调在预训练模型基础上完成图像编辑流程、交互流程和实验记录流程的统一组织，使系统具备基本的运行、展示和分析能力。

## 4.6 系统功能模块设计

结合当前实现情况，系统功能可划分为模型加载模块、整体编辑模块、局部编辑模块、结构保持编辑模块、界面交互模块以及实验记录模块六个部分。各模块在逻辑上相互配合，共同完成系统的整体运行。

模型加载模块主要负责系统启动时所需预训练模型的统一加载。由于不同编辑模式依赖的模型类型不同，该模块需要分别加载整体编辑、局部编辑和结构保持编辑对应的推理管线，并根据当前运行环境自动选择 CPU 或 GPU 设备。同时，为了提高系统在显存受限环境下的可运行性，模块还会在 GPU 环境中启用一定的显存优化策略。该模块的设计目标是为后续编辑操作提供稳定一致的模型调用基础。

整体编辑模块主要实现面向整幅图像的文字驱动编辑功能。用户输入原始图像和编辑指令后，系统将其送入 InstructPix2Pix 管线进行推理，从而完成整图语义修改。该模块适用于颜色变化、背景变化和整体风格调整等任务，其使用方式较为直接，但在部分情况下可能会对非目标区域产生影响。

局部编辑模块主要实现指定区域内的图像编辑功能。与整体编辑不同，该模块要求用户明确给出需要修改的区域。系统当前支持两种区域指定方式：一是上传黑白 Mask 图，二是在线绘制 Mask。无论采用哪种方式，模块最终都会将区域信息转换为标准黑白 Mask，并结合原图与文本指令一同送入 Inpainting 管线完成编辑。该模块的设计重点在于增强编辑的针对性，并提高局部修改场景下的可控性。

结构保持编辑模块主要用于在保留原始结构轮廓的基础上进行文字驱动编辑。该模块首先根据输入图像提取 Canny 边缘图，然后将边缘图作为结构条件输入到 ControlNet 管线中，使生成结果在一定程度上保持原图的主要结构关系。与整体编辑和普通局部编辑相比，该模块更适用于风格化变化或对原图轮廓保持有一定要求的场景。

界面交互模块主要负责系统的可视化使用流程设计。该模块通过 Gradio 将图像上传、Prompt 输入、参数设置、Mask 指定、结果展示和实验信息展示等操作组织在统一页面中，并根据不同编辑模式动态调整控件的显示状态。其设计目标在于简化用户操作流程，降低系统使用门槛，并为论文截图和答辩演示提供直观界面。

实验记录模块主要负责实验过程中的结果保存与信息留档。系统在每次编辑完成后，会自动保存输入图像、输出图像以及必要的控制图像，同时生成实验信息摘要，并将关键参数追加写入 CSV 实验日志文件中。该模块的作用不仅在于保存实验结果，也在于为后续结果对比、案例整理和论文分析提供依据。

总体来看，各模块分工较为明确。模型加载模块提供基础模型支持，三类编辑模块完成核心图像编辑任务，界面交互模块负责组织用户操作过程，实验记录模块负责整理和保存运行结果。通过这些模块的协同工作，系统形成了较为清晰的功能结构。

## 4.7 关键数据与文件组织设计

为了便于系统运行过程中的结果管理、实验整理和论文材料归档，本系统对输入输出数据、实验日志以及案例材料进行了统一的文件组织设计。相较于仅关注模型推理结果的简单实验脚本，这种组织方式更有利于后续的重复实验、案例检索和论文插图整理。

在运行数据方面，系统设置了 `data` 目录用于保存实验过程中产生的输入图像和输出图像。其中，输入图像目录主要保存用户在编辑过程中实际使用的原始图像副本，输出图像目录主要保存各模式推理生成的结果图像。对于结构保持编辑模式，系统还会额外保存 Canny 控制图，以便后续分析结构约束对结果的影响。通过这种方式，可以将每次实验的原始输入与最终输出对应保存，便于后续追踪和比较。

在项目文档方面，系统设置了 `docs` 目录用于保存与论文写作和项目迭代相关的记录文件。其中，实验日志文件主要采用 CSV 格式保存，用于记录每次实验的时间、提示词、推理参数、图像尺寸、输入路径和输出路径等内容。相较于仅保存最终图像，CSV 记录方式能够进一步保留实验参数信息，从而提高实验过程的可追溯性。除实验日志外，系统还在该目录下维护版本记录文件和案例索引文件，用于说明各阶段功能演进情况以及典型案例的整理情况。

在案例材料方面，系统设置了 `assets` 目录用于集中保存具有代表性的实验结果。根据当前项目实现，案例可进一步划分为整体编辑成功案例、整体编辑问题分析案例、局部编辑案例以及结构保持编辑案例等类别。通过对案例目录进行分类管理，可以在论文写作过程中更方便地选取成功案例、失败案例和对比案例，并减少后期重复整理的工作量。

从工程实现角度看，这种文件组织方式具有两方面作用。一方面，它能够将核心代码、运行结果和论文支撑材料分开管理，降低项目结构混乱的可能性；另一方面，它有助于形成较规范的实验留档机制，使系统不仅能够完成图像编辑任务，还能够对实验过程进行记录与整理。对于本科毕业设计而言，这种面向实现与论文双重需求的文件组织方式具有实际意义。

此外，本章还对系统总体架构、功能模块以及关键文件组织方式进行了设计说明，展示了整体编辑、局部编辑和结构保持编辑三种模式在系统中的组织方式，以及输入输出图像、实验日志和案例材料的管理方式。通过上述设计，本系统在预训练模型基础上实现了多模式文字驱动图像编辑，并形成了较清晰的工程结构，为后续系统实现与实验分析奠定了基础。
